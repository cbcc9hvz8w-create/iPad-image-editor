# SnapCanvas v1.6.0

iPadで保存済み画像をすばやく整え、Goodnotesなどへ渡すための完全オフライン画像編集PWAです。画像処理はブラウザ内で完結し、画像をサーバーへ送信しません。

## v1.6.0の変更

- 書き出した最終画像を画素単位で再検査し、透明・白・黒の外周を最後に強制削除
- 透明背景と不透明な黒い画像をアルファ値で区別し、黒い医用画像も正しく切り出し
- 「保存準備中…」で保存ボタンを無効にする仕様を撤去し、写真保存を常時操作可能に修正
- 事前準備済みファイルがあれば即共有し、未準備でも従来経路で保存を続行

## v1.5.0の変更

- 1本指移動と2本指拡大・縮小を復元し、2本指回転だけを固定
- 画面上の操作はそのまま維持し、保存時だけ縮小率を実寸pxへ変換して外周背景を除去
- 写真共有用ファイルを編集完了後に事前準備し、保存ボタンを押した瞬間にApple共有画面を開始
- 準備が終わるまでは保存ボタンを「保存準備中…」にして、iPadの共有権限が切れる失敗を防止

## v1.4.0の変更

- 2本指ピンチを、固定キャンバス内の縮小ではなく画像そのものの実寸px変更へ修正
- 旧版で縮小された画像も、保存時に縮小率を実寸へ変換して透明・白・黒の外周背景を除去
- 旧縮小データの位置と倍率を、保存時に余白なしの実寸へ変換
- `IMG_4350.PNG`で確認した623×640キャンバス内の約395×405画像を、余白なしの395×405として保存

## v1.3.0の変更

- 外周背景の無効化設定を廃止し、読み込み時と保存直前に必ず再検出
- 「端末へ直接保存」を廃止し、iPadでファイルのプレビュー画面へ移動しないよう修正
- 右上と保存画面の主ボタンを、どちらも写真保存用の共有へ統一
- 新版をアップロード後、古いService Workerを待機させず自動更新

## v1.2.0の変更

- 画像を開いた時点で白・黒の外周背景を削除し、実画像だけを表示
- v1.1.0で保存した背景付き画像も、再開時に自動修正
- プリセットと幅・高さの数値入力の両方で背景なしリサイズ
- 画面右上の「写真へ保存」から、設定画面を介さず共有画面を表示

## v1.1.0で追加した安定化

- 画像と編集状態を端末内へ自動保存し、終了・再読み込み後も最後の確定地点から再開
- 白または黒の単色外周余白を検出し、画像そのものを希望寸法へ再サンプリング
- 2本指操作は拡大・縮小だけに固定し、指の角度では回転しない
- 一括処理は1枚ごとに端末へ保存し、中断した位置から再開
- 更新確認、更新内容の表示、安全な適用、以前のキャッシュへ戻す操作
- 容量不足・破損ファイル・未対応形式などを分類し、復旧方法を表示

## iPadへのインストール

1. 公開したSnapCanvasのURLをiPadのSafariで開きます。
2. 共有ボタンを押します。
3. 「ホーム画面に追加」を選びます。
4. ホーム画面のSnapCanvasアイコンから起動します。

最初の1回はオンラインで開いてください。アプリ一式が端末へ保存された後は、通信がない状態でも画像編集を利用できます。

## 保存方法について

- **画面右上の「写真へ保存」**: 保存設定を開かず、1回のタップでAppleの共有画面を表示します。最後に「画像を保存」を選ぶと写真ライブラリへ入ります。
- **保存設定内の「写真へ保存」**: 保存形式などを確認してから、同じ共有画面を開きます。
- **画像をコピー**: Goodnotesなどを開き、そのまま貼り付けます。

iPadのWebアプリには、確認なしで写真ライブラリへ直接書き込む権限がありません。共有画面を完全に省いて「写真」へ保存するには、PhotoKitを使うネイティブiOSアプリ版が必要です。

## GitHub Pagesへ手動公開する場合

`github-dist`フォルダの中身だけを、GitHubリポジトリのルートへアップロードします。GitHubで **Settings → Pages** を開き、次のように設定します。

- Source: `Deploy from a branch`
- Branch: `main`
- Folder: `/(root)`

保存後、同じ画面に表示される **Visit site** からアプリを開けます。リポジトリ直下に`index.html`が見えていることを確認してください。

## GitHub Actionsで自動公開する場合

ソース一式をアップロードし、**Settings → Pages → Source** を`GitHub Actions`に設定します。`.github/workflows/pages.yml`が、mainブランチの更新ごとにiPad用PWAをビルドして公開します。

## リリース名の統一ルール

APKG-Simulatorと同じ形式で、配布フォルダとZIPの名前を必ず`SnapCanvas-vX.Y.Z`に統一します。

- 例: `SnapCanvas-v1.2.0` / `SnapCanvas-v1.2.0.zip`
- バージョンは常にメジャー・マイナー・パッチの3桁表記
- `Stable`、`iPad-PWA`、`GitHub-Ready`などの追加語は付けない
- 旧版を上書きせず、新版を別フォルダへ出力する

## ローカル開発

Node.js 22.13以降とpnpm 11.19以降を使用します。

```bash
corepack enable
pnpm install
pnpm dev
```

GitHub Pages用の静的ファイルを作る場合：

```bash
pnpm build:pages
```

生成先は`github-dist`です。

## 主な機能

- JPEG / PNG / WebP画像の読み込み
- 外周余白を除いた実画像リサイズ、切り抜き、手動回転、反転、傾き補正
- 2本指の拡大・縮小（回転固定）
- 明るさ、コントラスト、彩度、シャープ、モノクロなどの調整
- PNG / JPEG書き出し、JPEG品質・目標容量の指定
- JPEGのEXIF情報を保持または削除
- 変更履歴、編集前後の比較、設定プリセット
- 自動保存と作業再開
- チェックポイント付き複数画像一括処理
- アプリ内の更新確認・適用・以前のキャッシュへの復帰
- ホーム画面からの全画面起動とオフライン利用

## プライバシー

読み込んだ画像、編集状態、処理途中の出力は、作業再開のため端末内のIndexedDBへ保存されます。サーバーへは送信されません。アプリの「その他」から端末内の作業データを削除できます。
